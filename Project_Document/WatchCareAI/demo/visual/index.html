守望 AI 在合法授权下接入家庭摄像头，由家庭边缘节点在本地完成实时 AI 分析—— 原始视频不出家门；只有疑似跌倒、长时间倒地、危险区域进入、设备异常等 结构化风险事件才会上报云端，再由云端分级推送给监护人， 并形成「通知 → 确认 → 升级 → 归档」的完整处置闭环。

01

三个设计原则

下面四个场景和工作流中的每一步，都遵守这三条原则（对应软件设计方案 0.2 / 5.2 / 7.3 节）。

边缘优先

原始视频不出家门

iPhone 退到后台就无法持续分析（iOS 平台约束），所以全天候分析放在家庭边缘节点。 云端默认只接收事件类型、时间、置信度等元数据；事件短片加密上传且可完全关闭。

多阶段复核

单帧结果不直接报警

「人体检测 → 匿名跟踪 → 姿态 → 时序 → 候选 → 复核」多级融合。 快速坐下、正常躺卧不会触发报警；倒地后还要经过静止计时复核才升级为 L3。

报警闭环

不是发一条通知就结束

L1/L2/L3 分级通知；超时未确认自动升级给备用联系人； 每次状态流转都记录操作者、时间和原因，误报反馈用于阈值优化。

四个虚拟场景

监控画面为示意图（SVG 绘制），但叠加的检测框、骨架点、区域多边形使用的坐标体系与真实系统完全一致 （归一化坐标 x,y ∈ [0,1]，设计方案 3.3 节）。右侧是系统在该时刻的完整推理链。

① 老人跌倒 → L3 ② 儿童进入危险区 → L2 ③ 快速坐下 → 不报警 ④ 摄像头离线 → L1

为什么场景③不报警：跌倒 vs 快速坐下

时序特征真实跌倒（场景①）快速坐下（场景③）
垂直下降幅度52% 画面高度20% 画面高度
下降用时420 ms（急坠）1500 ms（受控）
躯干角度78°（接近水平）15°（保持直立）
倒地后静止25 s 未起身—（不适用）
规则链结论生成候选 → 复核通过 → L3不生成候选，不产生任何上报

05

事件生命周期与三种结局

所有状态变化都记录操作者、时间、原因与追踪编号（设计方案 4.3 节）。 命令行演示 demo/demo.py --auto 会完整播放这三种结局。

结局 A · 确认并处置完成
  1. CREATED → NOTIFIED 推送送达女儿
  2. → ACKNOWLEDGED 电话确认老人状态
  3. → RESOLVED 物业上门确认安全
结局 B · 标记误报
  1. CREATED → NOTIFIED 推送送达女儿
  2. → FALSE_POSITIVE 查看关键帧：靠垫掉落
  3. 误报反馈进入阈值优化数据集
结局 C · 超时升级
  1. CREATED → NOTIFIED 5 分钟无人确认
  2. → ESCALATED 升级通知儿子 + 短信
  3. → ACKNOWLEDGED 儿子赶往现场
