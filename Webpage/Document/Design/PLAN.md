版本 v1.0 · 2026-08-01 · 维护：pulsepilot 团队

## 1. 项目背景与目标

- 任务来源：创造营团队介绍页面作业（见 `Document/Mission/demand.md`），要求 Hero 区域、团队成员、项目介绍、参赛目标、服务群体五类信息完整呈现，并部署上线获得公开链接。
- 现状：项目题目已确定为「守望 AI（WatchCare AI）」。v1 已完成团队介绍全部内容与整站视觉框架，项目板块的产品定位、服务群体与核心功能已回填（痛点分析待数据核实后填入）。
- 目标：题目公布后 1 天内补齐内容，2 天内完成部署，拿到固定公网 URL。

## 2. 设计系统分析

> 设计令牌（色彩 / 字体 / 间距 / 阴影 / 动效 / 响应式断点 / 无障碍）的最终版本统一记录于同目录 **`DESIGN_SYSTEM.md`**，本节不再重复维护，以该文件为准。

设计要点摘要（详见 `DESIGN_SYSTEM.md`）：

- **风格**：纸墨（Paper & Ink）× 信号红（Signal Red）。暖白纸底 + 深墨文字，单一信号红 `#E03E26` 作为品牌记忆点，呼应队名 pulse（脉搏/心跳）。全站无渐变、无装饰性色块，对应作业「低 AI 味、有设计感」的加分要求。
- **字体**：无衬线栈（Avenir Next / Segoe UI / PingFang SC / Microsoft YaHei）用于正文标题；等宽栈（SF Mono / Cascadia Mono / Consolas）用于编号、标签、数据，提供工程感。大标题字重 900 + 负字距。
- **栅格**：版心 1120px、8dp 间距网格、圆角 8px；断点 1024 / 768 / 640px。
- **动效**：心电波形（Canvas 2D，PQRST 高斯叠加）、入场上浮淡入（IntersectionObserver）、状态点脉冲、卡片悬停升起；均尊重 `prefers-reduced-motion`。
- **品牌元素**：双色 wordmark（pulse 墨色 + pilot 信号红）、心电脉冲线 logo、队员照片缺省单字母 monogram（Y / H / C / L）。

## 3. 技术现状（v1）

- 单文件 `Page/index.html`（约 800 行），零依赖、零构建，双击即可打开。
- 照片双通道：页面点击/拖拽上传（Canvas 压缩至 900px 存入 localStorage）+ `Resource/Photos/` 目录按约定文件名自动加载（部署后全员可见）。
- 已用无头 Chrome 截图验证桌面（1440px）与平板（780px）渲染；已修复 `prefers-reduced-motion` 下心电线 resize 后不重绘的缺陷。
- 待部署：本机无 GitHub CLI / Node，需一次账号授权后推送（见 4.4）。

## 4. 开发计划

### 4.1 阶段 0 — 团队介绍 v1（已完成）

Hero、成员卡片、项目占位区、参赛目标、页脚，以及照片上传交互。

### 4.2 阶段 1 — 题目公布后回填内容（T 日 → T+1）

1. 替换 Hero 定位句中的「领域待定」，按 `demand.md` 三维度（产业创新 / 社会创新 / 创意引擎）选定表述。
2. 项目板块回填：题目 + 一句话简介（替换 `.ph-window`）、2–3 个核心功能（填入 `.feat-slot`）、痛点三层（填入 `.pain-row .v`）、服务群体。
3. 导航状态胶囊由「题目待定」改为正式题目名。
4.（加分项）提炼 2–3 个核心亮点与创新点。

### 4.3 阶段 2 — 素材与校对（T+1 → T+2）

1. 收集四人照片，按 `Resource/Photos/README.md` 命名放入 `Resource/Photos/`（localStorage 上传仅本机可见，正式照片必须进目录）。
2. 校对分工与技能标签（当前为按专业推断的占位内容）。
3. 补充李自胜毕业去向（当前仅有本科信息）。
4. 确认姓名简繁体写法、队长联系方式（可选）。

### 4.4 阶段 3 — 部署上线（T+2）

- 首选 GitHub Pages：固定 URL `https://<用户名>.github.io/<仓库>/`。
- 备选 Vercel / Netlify（支持拖拽部署，作为大陆访问的备用链接）。
- 上线后做全设备回归，并将链接提交至作业问卷。

### 4.5 阶段 4 — 加分优化（时间允许时）

- favicon 与 OG 分享图（微信 / QQ 分享卡片）。
- 成员一句话自我介绍的展开交互。
- 无障碍与性能走查（对比度、alt 文本、Lighthouse ≥ 95）。

### 4.6 阶段 5 — 路演汇报页（已完成）

1. 新增 `Page/roadshow.html`，以评委和合作方视角重组“痛点 → 方案 → 差异化 → 收入模型 → 总结 → 团队”的销售叙事。
2. 关键行业数据沿用项目企划书与趋势调研报告；价格与营收推演以参考简报为准，并对情境假设作可见标注。
3. 全站五个页面的桌面导航、移动端导航与黑色页脚统一增加「路演汇报」入口。
4. 路演页保持零依赖、单文件结构，并提供 1024 / 840 / 560px 响应式适配与 `prefers-reduced-motion` 动效降级。
5. 首屏按《守望AI_封面.pptx》改为奶油白双栏版式，复用封面居家照护插画，并将路演页面可见文案统一为繁体中文。
6. 现状数据区按《守望AI_5分鐘商業路演_原風格市場版.pptx》重做为三段市场信号：两张老龄化／长者跌倒负担图表及一张儿童非致死跌倒图表；移除旧四格数据带与痛点卡，采用短结论、强数字、响应式图表和逐图来源说明。
7. 参考《守望AI_5分鐘商業路演_PRO.pptx》第 4 页，在三张详细图表后增加「照护缺口」因果总结层，并强化首屏中英产品名，使路演从品牌识别到问题结论更快进入重点。
8. 参考 PRO 简报第 5 页，先呈现四类现有方案不足，再进入 WHY US 三项优势；采用「已有能力／关键限制／市场缺口」短句结构，明确守望 AI 在主动发现、稳定使用、真实家庭适配、隐私与离线可用上的差异化。
9. 参考 PRO 简报第 8 页，将 GO-TO-MARKET 重构为家庭订阅、机构 SaaS、摄像头品牌 SDK 三个收入引擎；删除 EXECUTION，将 THE ASK 调整为第 05 节总结，并在页面末尾加入四位成员介绍。
